# makonbook-web: handoff

The MakonBook web: a landing page at **makonbook.uz** and the student and
teacher web app at **sat.makonbook.uz**, both from one new repo,
**`nazacd/makonbook-web`**, deployed as one small container on the VPS.

Read this whole file first. Commit it to the new repo as `docs/handoff.md`, and
keep a short `CLAUDE.md` at the root that points to it.

---

## 1. What exists already

| Repo | What | Read first |
|---|---|---|
| `nazacd/makonbook-api` | Go API at `https://api.makonbook.uz`, its admin panel (`web/admin`, React), deploy files | `api/openapi.yaml` (the contract), `docs/platform-spec.md` (the product), `deploy/DEPLOY.md` (the VPS) |
| `nazacd/makonbook-mobile` | Expo / React Native app for students and teachers | `AGENTS.md`, `MOBILE-DESIGN.md` |

The web app is a **new client of the same API**, next to the mobile app. Its
first version needs **no API changes**.

The admin panel in `makonbook-api/web/admin` uses the stack below too
(Vite, React, TanStack Query, openapi-fetch with generated types). Look at
`src/api/` there for the pattern.

## 2. Decisions already made (don't reopen)

- **Separate repo**, not inside `makonbook-mobile` (the Expo web build is a
  phone app in a browser, and it currently crashes on web) and not inside
  `makonbook-api`.
- **Two sites, one repo, one container:**
  - `makonbook.uz`: the landing page (`landing/`).
  - `sat.makonbook.uz`: the app (`app/`).
- **The landing page is already designed:** a single HTML file the user will
  attach (`makonbook_4.html`). Keep its look; don't redesign it.
- **Not in the web:** parent mode, QR scanning (phones only), the Level Check
  placement test.
- **Stack for `app/`:**
  - Vite, React, TypeScript (strict), React Router, TanStack Query.
  - `openapi-fetch`, with types generated by `openapi-typescript` from
    `makonbook-api/api/openapi.yaml` (copy the file in, or fetch it in a
    script).
  - Tailwind.

## 3. Scope of the first version

**Students**
1. Sign in (phone number or username + password), including the forced
   change of the temporary password, and sign out.
2. Classes: groups and schedule (`GET /v1/me`), next class, attendance per
   group (`GET /v1/me/attendance`).
3. **Practice, the main reason for a laptop:**
   - catalog, test page, taking a test, results, question review;
   - laid out like Bluebook (passage left, question right for Reading and
     Writing; the Desmos calculator for Math; timed modules);
   - history from `GET /v1/me/practice/attempts` (includes answers);
   - finished attempts uploaded to `POST /v1/practice/attempts`.
4. Words: the vocabulary deck and study sessions with FSRS, synced with the
   phone (section 5).
5. Profile: username, password, parent code (`GET /v1/me/parent-code`, to
   show only).

**Teachers**
1. Today: lessons by date (`GET /v1/teacher/lessons?date=YYYY-MM-DD`).
2. Attendance:
   - open it (`POST /v1/attendance/sessions`);
   - show the **rotating QR full screen**, for the classroom projector;
   - live list (poll `GET /v1/attendance/sessions/{id}` every 3 s while open);
   - marks (`PUT …/marks/{client_id}`) and finish.
3. Their groups' practice (`GET /v1/teacher/groups/{id}/practice`) and words
   (`…/vocab`).

## 4. Milestones (one at a time, each deployable)

- **M0:** repo scaffold, CI (typecheck, lint, build), Dockerfile, the landing
  page served as it is, the app's empty shell.
- **M1:** sign-in, forced password change, sign-out, Classes, attendance view.
- **M2:** Practice (the biggest part).
- **M3:** Words.
- **M4:** Teacher screens.

## 5. Logic that must match exactly (copy it, don't rewrite it)

These are plain TypeScript in `makonbook-mobile`. Copy them into
`app/src/lib/…`, keep the "must match" comments, and note where each came
from. If one changes in the app, it must change here too.

| From `makonbook-mobile` | Must match | Notes |
|---|---|---|
| `src/lib/practice/grade.ts` | API `internal/practice/scoring.go` | The server grades again; the phone's grade only shows until then |
| `src/lib/practice/types.ts` | API `PracticePackage` | The package format |
| `src/lib/practice/run.ts` | the app | Modules, timing (Reading and Writing 2 × 32 min, Math 2 × 35 min) |
| `src/lib/vocab/scheduler.ts` | every device | `ts-fsrs` **pinned to exactly `5.4.2`**, no fuzz, 90 % retention; replaying the same log must give the same cards everywhere |
| `src/lib/vocab/types.ts` | API vocab endpoints | |
| `src/lib/attendance/code.ts` | API `internal/attendance/token.go` | QR: `window = floor(unix/10)`, `sig = first 16 chars of base64url(HMAC-SHA256(secret, "<session>:<window>"))`, link `makonbookmobile://att/<session>/<window>/<sig>`; uses `@noble/hashes`, which works in browsers |

**Question text** is the API's content format: paragraphs, `\( \)` and
`\[ \]` math, `*i*`, `**b**`, `<u>`, lists, pipe tables, `![alt](r2:key)`
images. It's described in `makonbook-api/docs/platform-spec.md` §9.2, and the
app's renderer is `src/components/practice/RichContent.tsx`. In the browser,
render math with MathJax 3 and set only `\( \)` / `\[ \]` as delimiters.
**Never `$…$`**: prices like "$29" would turn into math. Image links in a
package are presigned R2 URLs valid for 6 hours, fine for `<img src>`.

## 6. API facts you'll need

- **Errors:** `{"error": {"code", "message", "request_id"}}`. Branch on
  `code`, never on `message`.
- **Status codes:**
  - 401 on a signed-in request means the session is gone: sign out locally.
  - 429 comes with `Retry-After`.
- **Sign-in:**
  - `POST /v1/auth/login` with `{login, password, device_id}` returns
    `{token, expires_at, user}`.
  - `device_id`: one random UUID per browser, kept in `localStorage`.
  - Send the token as `Authorization: Bearer <token>`. Keep it in
    `localStorage` for now, and set a strict Content-Security-Policy.
    httpOnly cookie sessions would need API work; leave them for later.
- **Forced password change:** while `user.must_change_password` is true, only
  `/v1/me`, `/v1/auth/password` and `/v1/auth/logout` work (403
  `password_change_required` elsewhere). Show only the "choose a password"
  screen, with a way to sign out.
- **School time:** schedules and "today" are Tashkent time (UTC+5 all year).
  Copy `src/lib/schedule.ts` from the app for the date maths.
- **Desmos:** the key comes from an environment variable
  (`VITE_DESMOS_API_KEY`, in `.env`, git-ignored). Never commit it. Ask the
  user whether the key allows the `sat.makonbook.uz` domain.

### Local development

Use the Vite dev server's proxy: `/v1` → `https://api.makonbook.uz`, so the
browser sees one origin and there's no CORS. In production the edge nginx
does the same (section 7).

### Test accounts

The production API has demo accounts:
- `demo.student`: classes, attendance, practice results;
- `demo.teacher`: has an "open all day" class, so attendance can be taken at
  any time.

Ask the user for the password and keep it out of commits and chat logs.

## 7. Deployment (same VPS as the API)

The VPS runs an **edge nginx** container, `makonbook-nginx`, on the Docker
network `sat_makon_network`. Its config is
`/opt/sat-makon/makonbook/nginx/default.conf`; certificates come from
certbot (webroot `/var/www/certbot`). `makonbook-api/deploy/nginx-api.conf`
shows the pattern to copy:
- PART 1: HTTP plus the ACME challenge, reload, issue the certificate.
- PART 2: HTTPS, added only once the certificate exists. A missing
  certificate file stops nginx from loading, which would take every site on
  the edge down.
- A variable upstream with `resolver 127.0.0.11`, so nginx still starts if a
  container is down.

**This repo builds one image, `nazacd/makonbook-web`:**
- `nginx:alpine` with both builds inside: `/srv/landing` and `/srv/app`.
- Two server blocks on port 8080, chosen by `Host`:
  - `makonbook.uz`: the landing page;
  - `sat.makonbook.uz`: the SPA, with `try_files $uri /index.html`.
- Long cache for hashed assets, no cache for `index.html`.
- It runs read-only like the API containers (`read_only: true`), so mount
  tmpfs for nginx's cache and run directories.

**Edge nginx, new blocks:**
- `makonbook.uz` (and `www.`): everything → `makonbook-web:8080`.
- `sat.makonbook.uz`:
  - `/v1/` → **`makonbook-api:8080` directly**, with the same headers as
    `nginx-api.conf`. Don't send it through the web container: the API reads
    the last `X-Forwarded-For` entry for its per-IP limits, and a second
    proxy would put the web container's address there.
  - everything else → `makonbook-web:8080`.
- **Before changing `makonbook.uz`, ask the user what serves it today.** The
  edge already has a certificate covering makonbook.uz (a SAN certificate),
  so something is there.

**Running it:**
- A `docker-compose.yml` in `/opt/makonbook-web`, joining the external
  network `sat_makon_network`.
- A GitHub Actions workflow builds and pushes the image on push to `main`.
  Copy `makonbook-api/.github/workflows/docker.yml`; it needs the secrets
  `DOCKERHUB_USERNAME` and `DOCKERHUB_TOKEN`, which the user adds.
- Write the steps in `deploy/DEPLOY.md`, as the API repo does.

## 8. Landing page notes

- **Links:** the "Practice" and "Start practicing" buttons go to
  `https://sat.makonbook.uz`. On phones, offer the app instead (the Google
  Play link comes from the user; the practice site is made for laptops).
- **Weight:** it loads three.js r128 and MathJax 3.2.2 from cdnjs, plus
  Google Fonts. Most visitors are on phones and mobile data, so host the
  scripts in `landing/` and load them after the page has shown. Check that
  the first screen appears fast on a slow phone.
- **Look:** the landing page keeps its own style (dark, Bricolage Grotesque
  and Geist). The **app** follows the mobile app's design: tokens in
  `makonbook-mobile/src/global.css`, rules in `MOBILE-DESIGN.md`, light and
  dark themes, Bitter for titles.

## 9. Ground rules

- **Never commit secrets:** API keys, the Desmos key, passwords, tokens, R2
  credentials. Never ask the user to paste them into chat; they go in `.env`
  files on the machine or the server.
- **Repos are public:** keep student data and test content out of the repo,
  screenshots and fixtures included.
- **Pull requests:** don't open them unless the user asks; push to the branch
  they name.
- **Before calling a step done:** typecheck, lint and build must pass. Try
  the flow in a real browser (Playwright is fine) at laptop and phone widths.
- **Questions:** if the API seems to lack something, read `api/openapi.yaml`
  and `docs/platform-spec.md` first; then describe the API change to the user
  rather than working around it in the web app.
